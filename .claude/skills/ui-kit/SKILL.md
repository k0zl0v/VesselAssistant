# UI kit — правила интерфейса

Макеты: `docs/ui/artboards/*.dc.html` (точные значения px и hex, читаются
`grep`), скриншоты — `docs/ui/png/`, порядок внедрения — `docs/ui/README.md`.
Токены — `src/styles/tokens.css` (исходник: `docs/ui/tokens.css`).

**Перед работой над экранами кранов, OGV, SOF или профиля судна читать
`docs/ui/excel-reference.md`** — там разобрано, чем реальная работа
операторов шире текущей модели данных, и перечислены открытые вопросы.

При противоречии макета и ТЗ побеждает ТЗ: макет показывает подачу, а не
бизнес-правила.

## Ни одного хардкода цвета и размера

Все значения — через переменные из `tokens.css`. Нужного токена нет — добавить
его туда, а не писать хекс в JSX или в `App.css`. Исключение одно: цвета
грузов, вычисляемые из данных, берутся через явный маппинг
`SFM → var(--cargo-sfm)`, `WHEAT → var(--cargo-wheat)`, остальное —
`var(--cargo-fallback)`.

## Числа

1. **Три знака после запятой всегда**, даже у целых: `4 082.000`. Формат
   даёт `formatTons` из `src/calc/round.ts` — не дублировать `toFixed(3)`
   по компонентам.
2. **Разряды разделяются U+202F** (узкий неразрывный пробел). Он не ломает
   вставку в Excel и читается на судовом мониторе. Точка — десятичный
   разделитель в обеих локалях, чтобы цифры совпадали с XLSX-экспортом.
3. **`font-family: var(--font-mono)` + `font-variant-numeric: tabular-nums`**
   на каждой числовой ячейке, метрике и идентификаторе (класс `.num`).
4. **Проценты — один знак**: `58.0 %`, с неразрывным пробелом перед `%`.
   **Коэффициенты кранов — три знака**: `1.060`, не `1.06`.
5. **Отрицательные значения** — минус U+2212 и `var(--danger)`:
   `−142.500`. Отрицательный остаток трюма — ошибка расхождения плана и
   факта (ТЗ §8.3). У трюмов OGV отрицательный остаток означает другое —
   загрузку сверх cargo plan, и это штатная ситуация: тот же цвет, но
   подпись «сверх плана», а не «ошибка».
6. Округление — только на границе отображения. Промежуточные расчёты
   остаются полной точностью.

## Таблицы

- Ширина — по окну, без `max-width` по центру. Горизонтального скролла на
  1440 px быть не должно.
- Высота строки 40 px, шапка `var(--surface-sunken)`, метки колонок
  10 px / 600 / `letter-spacing: var(--tracking-col)`, верхним регистром.
- Числовые колонки выровнены вправо, текстовые — влево. Единица измерения
  уходит в заголовок колонки (`ОБЪЁМ, м³`), а не в каждую ячейку.
- Ключевая колонка («Остаток») выделяется фоном `var(--surface-sunken)` и
  весом 600, а не цветом.
- Итоговая строка — в `<tbody>` последней строкой, фоном и весом 700.
- Шкала заполнения считается от вместимости при 98 %: до 75 % — подпись
  `var(--ink-muted)`, от 75 % — `var(--warning-ink)`, от 95 % —
  `var(--danger)`. Сама шкала окрашена по грузу.

## Трюм показывает три величины, а не одну

Оператор в Excel читает по каждому трюму процент заполнения **и** свободный
объём. В UI обязаны быть все три:

| Величина | Откуда | Где показывать |
|---|---|---|
| `remain_tons` | уже есть | колонка «Остаток» |
| заполнение, % | `100 − empty_volume_percent` | полоса профиля судна |
| свободный объём, м³ | `volume_m3 − remain_tons × sf` | полоса профиля судна |

Новых полей в БД для этого не нужно. Контрольные значения для трюма №5:
свободно `5 959.105` м³, заполнение `44.7 %`.

## Краны видны на рабочих экранах

Крановая поправка — не справочник, а рабочий лист смены: в исходном файле
это отдельный лист, который оператор заполняет каждую вахту. Поэтому:

- У крановой поправки **свой пункт в навигации**, не вкладка справочников.
- На Load Plan краны присутствуют в полосе профиля судна: название,
  рабочий коэффициент, последняя операция.
- Форма выгрузки обязана спрашивать кран и режим операции и показывать
  скорректированный вес тут же.

**Режимов операции четыре** — `ИЗ СЕБЯ`, `ПРЯМОЙ ВАРИАНТ`, `В СЕБЯ · левый
борт`, `В СЕБЯ · правый борт`. По бортам делится только `В СЕБЯ`. Не
изобретать свои названия и не сводить их к паре «тип + борт», пока модель
данных не приведена в соответствие (см. `excel-reference.md` §2).

**В остатки трюма и в Load Plan списывается вес по судовым весам, а не
скорректированный.** Скорректированный — отдельная строка для листа
CRANE CORR. Нарушение этого правила ломает сходимость с контрольным файлом:
`Discharged = 2 001.000` — это сумма весовых, а не корректированных.

Коэффициент выводится из истории замеров `(судно, дата, коэффициент)` с
ручным исключением выбросов. В интерфейсе показывать и среднее по
включённым, и принятое в работу значение — они законно расходятся, потому
что принятое выбирает оператор.

## Опасные операции объясняются цифрами, а не алертом

`window.confirm`, `window.alert` и `window.prompt` в UI запрещены.

Перегруз (AT-05, ТЗ §8.2) показывается inline-панелью рядом с полем ввода:
вместимость 98 %, текущий остаток, свободно, добавляемый тоннаж, проекция и
величина перегруза — все шесть чисел одновременно, плюс шкала с отметкой
лимита. Подтверждение — чекбокс с текстом про запись в журнал аудита;
основная кнопка заблокирована, пока он не отмечен, и в этом состоянии
окрашена в `var(--danger)`, а не в акцент.

Выгрузка показывает превью LIFO **до** подтверждения: какие слои затронуты,
сколько списывается с каждого, что останется, и каким станет трюм. Для
превью `dischargeFromHold` вызывается на `structuredClone(layers)` — функция
мутирует вход, а превью не должно ничего менять.

## LIFO виден глазами

Порядок слоёв — всегда сверху вниз, верхний слой первым, помечен явно
(`СЛОЙ 2 · ВЕРХ`). Списанная часть слоя — штриховка
`var(--layer-discharged-fill)`, полностью закрытый слой — без заливки, с
пунктирной границей и подписью «слой закрыт». Высота блока пропорциональна
погруженным тоннам.

Ручной выбор нижнего слоя не предлагается нигде в интерфейсе (ТЗ §8.11) —
ни селектом, ни «расширенным режимом». Корректировка — отдельная операция.

## Ошибки

`String(err)` в разметку не попадает. Ошибки сервисов разбираются в
человеческий текст: `OVERLOAD:<json>` → панель перегруза, `SF must be > 0` →
сообщение под полем SF, `No active crane coefficient for …` → подсказка, что
на эту дату и режим коэффициента нет, со ссылкой на историю замеров.
Техническая строка может быть под катом «подробности», но не основным текстом.

## Состояния экрана

Обязательны все четыре, макеты — в `DesignSystem.dc.html`:

| Состояние | Подача |
|---|---|
| Пусто | Иконка, строка объяснения, одна кнопка действия. Не `<p class="hint">`. |
| Загрузка | Скелетон строк таблицы. Пересчёт рейса — до 2 с (ТЗ §7). |
| Ошибка данных | Карточка `var(--danger-soft)` с объяснением и действием. |
| Рейс закрыт | Чип «ЗАКРЫТ», ввод заблокирован, экспорт и аудит доступны. |

`busy` не должен гасить весь экран: блокируется только та форма, которая
отправляется. Полный `refresh()` рейса после каждого действия — источник
мигания, локальное обновление предпочтительнее.

## Доступность

- Настоящие `<button>`, `<a href>`, `<input>` + `<label for>`. Никаких
  `onClick` на `div` — Tab через них не проходит.
- Иконочные кнопки — с `aria-label`.
- Фокус виден всегда: `outline: 2px solid var(--accent)` либо
  `box-shadow: var(--focus-ring)`. Снимать `outline` без замены нельзя.
- Цель нажатия — минимум 30 px по высоте (компактные чипы) и 34 px для
  основных контролов.
- Контраст текста не ниже 4.5:1. Серый `var(--ink-faint)` — только для
  подписей 11 px и крупнее на белом, не для данных.

## i18n

Любая видимая строка — через `t()`. Новый ключ добавляется сразу в
`src/i18n/en.ts` **и** `src/i18n/ru.ts`, иначе `npm run typecheck` падает.
Единицы (`т`, `м³`, `%`) — тоже ключи. Названия режимов крановых операций
переводятся как термины: `ИЗ СЕБЯ` → `From own holds`, `ПРЯМОЙ ВАРИАНТ` →
`Direct transfer`, `В СЕБЯ` → `Into own holds`.
