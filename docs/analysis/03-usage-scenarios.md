# Сценарии использования на судне

> Зачем морякам вообще понадобилась программа: конкретные жизненные ситуации, выведенные из ТЗ (§1, §4, §5.2, §10, §12, §13.4). Термины — в [глоссарии](./02-glossary.md).

## Контекст всех сценариев

Судно-накопитель стоит на рейде. Грузовой помощник капитана работает на судовом ПК (часто ноутбуке) без интернета. Вокруг — реальная работа: баржи швартуются, кран гремит, погода меняется, таможня и агент требуют бумаги. Программа — его рабочий журнал и калькулятор одновременно.

## 1. Подход баржи с зерном (погрузка)

Баржа VELES швартуется к борту («all fast»). Помощник вводит партию: источник VELES, трюм №3, пшеница протеин 12.5, SF этого трюма, тоннаж. Если партия переполнит трюм сверх 98% — программа предупреждает и требует явного подтверждения (AT-05). После ввода партия ложится верхним слоем в стек трюма, и сразу виден обновлённый empty space — сколько ещё влезет.

## 2. Планирование следующей баржи

По радио сообщают: подходит баржа на 1500 т. Помощник открывает таблицу трюмов и смотрит «свободно 98%» по каждому — решает, куда распределить 1500 т, не нарушив ограничение заполнения (AT-01, AT-11 — у каждого трюма свой SF, поэтому «сколько влезет» у всех разное даже для одного груза).

## 3. Выгрузка на океанское судно (через OGV)

Началась отгрузка на судно-приёмник. Оператор выбирает груз из **имеющихся остатков** основного судна (руками цифры не вводятся — AT-12): 1177 т из трюма №3, 824 т из трюма №5 (AT-02). Система списывает по LIFO с верхних слоёв и автоматически пересчитывает грузовой план. Ручного переноса цифр между «журналом» и «планом», как в Excel, больше нет.

## 4. Запрос таможни: «чей груз на борту?»

После нескольких перевалок таможня хочет знать, сколько зерна каждого судна-источника осталось на борту. Оператор открывает стек партий по трюмам: сверху вниз видны слои, остатки по источникам, история списаний (FR-18). Отчёт экспортируется. Без программы это считалось вручную, и ошибка означала расхождение таможенного учёта.

## 5. Ведение SOF в течение суток

Каждое событие рейса — «NOR tendered», «начали погрузку», «дождь, работы остановлены», «формальности» — вносится с временем от/до, можно из шаблонов типовых формулировок. Программа ловит пересечения интервалов и корректно понимает `24:00` как конец суток (AT-04). Печатная форма SOF идёт на подпись капитану и агенту — это юридический документ, по которому потом считают, кто платит за простой судна.

## 6. Сверка крановых весов

Кран №2, левый борт, выгрузка: весы показали 100 т. Оператор выбирает кран/борт/тип операции — программа находит коэффициент, действующий на эту дату (например 0.95), и выдаёт истинный вес 105.263 т (AT-03). Коэффициент, не действующий для этой даты/операции/борта, применить нельзя.

## 7. Ежедневный отчёт

В конце суток — экспорт XLSX (Load Plan + SOF + OGV + Crane Corr., все числа в формате `0.000` — AT-13), печать, подписи. Файл уходит агенту или в офис при появлении связи. Структура файла намеренно повторяет привычный Excel — люди доверяют знакомому формату.

## 8. Передача рейса в офис

Перед заходом в порт помощник экспортирует рейс единым файлом проекта (FR-15) на флешку — офис открывает его у себя в той же программе. Это основной канал обмена «судно ↔ берег» в мире без стабильного интернета.

## 9. Смена компьютера / сбой

Судовой ПК умер (солёный воздух, качка, перепады питания — обычное дело). Восстановление из локального бэкапа на другом ПК (FR-14). Автобэкап делается при закрытии рейса и перед рискованными операциями (импорт, восстановление).

## 10. Миграция со старого Excel

В начале использования помощник импортирует существующий `Load St Plan+SOF.xlsx` (FR-12): программа разбирает 4 листа, заменяет формулы на значения, показывает превью и журнал ошибок импорта. Порог входа для команды, годами жившей в Excel, минимален.

## 11. Закрытие рейса

Груз сдан — рейс закрывается: автобэкап, статус «closed», далее только просмотр и экспорт. Правки задним числом — только корректировочным актом с записью в аудит (§8 п.7, п.11): это защита юридической и таможенной целостности документов.

## Почему им понадобилась именно программа (сводка мотивации)

| Боль в Excel | Что даёт программа |
|---|---|
| Ручной перенос цифр между 4 листами, расхождения | Единая база: один ввод — везде пересчёт |
| Формулы в ячейках, легко затереть | Ввод отделён от расчёта, формул в полях нет |
| LIFO «на глаз» → риск проблем с таможней | Автоматический стек слоёв, ручное нарушение невозможно |
| Шаблон привязан к KAVKAZ IV | Любое судно — параметр |
| Нет валидации (перегруз, минус-остатки, пересечения времени) | Проверки на вводе + подсветка ошибок |
| Неизвестно, кто и что поменял | Автоматический аудит-лог |
| Файл один, сломался — потеряли всё | Локальные бэкапы + файл проекта для офиса |
