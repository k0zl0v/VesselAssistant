## Покрытие приёмочных тестов

12 из 13 AT покрыты надёжно (LIFO — на двух уровнях: pure + интеграция с БД; есть rollback-тест транзакции; float-edge cases в overload guard). Слабое место — **AT-10 (protein)**: проверяется лишь хранение значения, нет теста на отклонение недопустимого и на вывод в документах.

5. «Все 13 AT покрыты» — верно локально, но 2 импорт-теста скипаются на CI.

## Технические риски и долги

1. **Zero e2e/Tauri-тестов** — все 113 тестов идут через NodeDb (better-sqlite3); реальный путь TauriDb → tauri-plugin-sql → прод-миграции не покрыт ничем.
2. **Нет crash-репортинга и файлового лога** — ни ErrorBoundary, ни window.onerror. Для offline-приложения лог-файл — единственный канал диагностики; белый экран на судне = неотлаживаемый инцидент.
3. **Неподписанные бинари** — на судовых ПК с корпоративными политиками SmartScreen может быть блокером, а не предупреждением.
4. **Нет автообновлений** (tauri-plugin-updater не подключён), процесс ручного обновления для пользователя не описан.
5. **better-sqlite3 — нативный модуль**: замечен NODE_MODULE_VERSION mismatch при смене Node (лечится `npm rebuild`); стоит зафиксировать версию Node (`.nvmrc`/`engines`).
6. **Perf-требование §7** (10 000 событий + 1000 партий ≤ 2 с) не проверяется ни одним тестом.
7. **Хорошее, что стоит отметить**: lazy-import ExcelJS выдержан (бандл ~285 KB), транзакционность мутаций систематична, дедуп-триггер audit_log при импорте — зрелое решение, регрессия против реального Excel — правильный фундамент доверия.
