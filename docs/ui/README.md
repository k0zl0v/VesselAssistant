# UI-макеты VesselAssistant

Дизайн десктопного интерфейса: 8 экранов, дизайн-система, состояния.
Живой канвас — в Claude (artifact «VesselAssistant — десктоп-интерфейс»),
здесь лежит его выгрузка, пригодная для чтения Claude Code.

## Что в папке

```
docs/ui/
├── README.md                 # этот файл — порядок внедрения и промпты
├── tokens.css                # дизайн-токены, первый файл к переносу в src/styles/
├── png/                      # скриншоты артбордов (выгрузить вручную, см. ниже)
└── artboards/                # исходники макетов — точные значения px и hex
    ├── canvas.json           # раскладка канваса, размеры кадров
    ├── Main.dc.html          # 1 · Load / Stowage Plan
    ├── CargoLayers.dc.html   # 2 · Слои груза (LIFO)
    ├── Sof.dc.html           # 3 · Statement of Facts
    ├── AddLot.dc.html        # 4 · Добавление партии + AT-05
    ├── Discharge.dc.html     # 5 · Выгрузка: превью LIFO
    ├── Documents.dc.html     # 6 · Документы и ревизии
    ├── Reference.dc.html     # 7 · Справочники + Crane Correction
    └── DesignSystem.dc.html  # 8 · Дизайн-система
```

## Как читать артборды

Это HTML: каждый экран — один самодостаточный файл с инлайновыми стилями.
Оттуда берутся **точные** значения: hex, размеры шрифта, отступы, высоты
контролов, ширины колонок. `grep` по ним работает:

```bash
grep -n "0B6E7F" docs/ui/artboards/*.dc.html   # где используется акцент
grep -n "font-size: 13px" docs/ui/artboards/Main.dc.html
```

Две оговорки:

- Файлы **не открываются в браузере напрямую** — они написаны в формате
  редактора Claude Design и ссылаются на `./support.js`, которого здесь нет.
  Для визуальной сверки используйте PNG (ниже) или сам канвас.
- Данные в макетах — не выдумка: все тоннажи, SF, вместимости и итоги взяты
  из `src/fixtures/kavkaz-iv.ts` и сходятся с Appendix C. On board
  `23 683.955`, Total Empty 98 % `15 881.924`, перегруз по AT-05 `130.460` т.
  Так что макет можно использовать как дополнительный контрольный пример.

### Скриншоты

Claude Code видит картинки, и для общей композиции они удобнее исходников.
В канвасе: **Share → Export → PNG**, выгрузить все артборды и положить в
`docs/ui/png/` под именами `Main.png`, `CargoLayers.png` и т.д.
Дальше в Claude Code достаточно `@docs/ui/png/Main.png`.

## Порядок внедрения

Снизу вверх: сначала то, что ничего не ломает, потом то, что трогает сервисы.

1. **Токены.** Перенести `docs/ui/tokens.css` в `src/styles/tokens.css`,
   импортировать в `main.tsx` перед `App.css`, подключить IBM Plex Sans/Mono.
   Затем переписать `App.css` на токены. Поведение не меняется.
2. **Оболочка.** `App.tsx`: вместо трёх вкладок — навигационный рельс на
   разделы ТЗ §10 и шапка рейса с судном, портами и датами. Контент-контейнер
   перестаёт быть `max-width: 1200px` по центру и занимает ширину окна.
3. **`HoldTable`.** Полная ширина, моноширинные числа с группировкой разрядов,
   колонка «Заполнение к 98 %» со шкалой, подсветка при ≥ 75 % и ≥ 95 %.
   Раскрывающаяся строка уходит — детали трюма живут на экране слоёв.
4. **`AddLotForm`.** Диалог вместо `form-row`. Панель живого расчёта
   (вместимость → свободно → проекция → перегруз) пересчитывается на каждый
   ввод. `window.confirm` заменяется inline-панелью с цифрами и чекбоксом
   подтверждения; кнопка отправки заблокирована, пока чекбокс не отмечен.
5. **`DischargeForm`.** Превью LIFO до подтверждения. Требует сухого прогона:
   `dischargeFromHold` мутирует переданные слои, поэтому для превью вызывать
   его на `structuredClone(layers)` — pure-функция это позволяет, менять
   `src/calc/discharge.ts` не нужно.
6. **`CargoLayersPage`.** Новый экран: стек слоёв по трюмам, остатки по
   судам-источникам (`OgvService.availableBySource`), история списания
   (`discharge_allocations` JOIN `operations`).
7. **`SofPage`, `DocumentsPage`.** Таймлайн по суткам, сводка сталии,
   история ревизий экспорта.

Шаги 1–3 стоит делать одним заходом, 4–7 — по одному, каждый в свою ветку.

## Чего в макете нет и что придётся решить

- **Экран ревизий предполагает, что экспорты сохраняются.** Сейчас
  `DocumentEngine` отдаёт файл и забывает о нём. Нужна таблица
  `document_revisions` (миграция + регистрация в `lib.rs` и в
  `__tests__/helpers.ts`) либо перечитывание папки рейса с диска.
- **Сводка сталии в SOF** (рабочее время, простой по погоде) — расчёта нет.
  Это чистая функция над интервалами, место ей в `src/calc/time.ts`.
- **Роли** (оператор / супервайзер / только просмотр) в макете не показаны,
  хотя ТЗ §7 их требует. Отдельная задача.
- **i18n.** Каждая новая строка — сразу в `src/i18n/en.ts` и `ru.ts`,
  иначе `npm run typecheck` не пройдёт. В макетах текст русский; английские
  формулировки для SOF-категорий уже есть в `services/sofCategories.ts`.

## Промпты для Claude Code

Сначала поставить скилл — он подхватывается Claude Code автоматически и
держит правила дизайн-системы (удалённые инструменты в `.claude/` писать не
могут, поэтому файл лежит рядом):

```bash
mkdir -p .claude/skills/ui-kit
mv docs/ui/ui-kit.SKILL.md .claude/skills/ui-kit/SKILL.md
```

Дальше промпты запускать в корне репозитория.

**Шаг 1–2, оболочка:**

> Прочитай `docs/ui/README.md` и `docs/ui/artboards/Main.dc.html`. Перенеси
> `docs/ui/tokens.css` в `src/styles/tokens.css`, подключи его и шрифты IBM
> Plex Sans/Mono в `main.tsx`, перепиши `App.css` на токены. Затем замени
> три вкладки в `App.tsx` на навигационный рельс и шапку рейса точно как в
> макете: рельс 232 px, разделы «Рейс» и «Данные», активный пункт — акцентом.
> Контейнер контента больше не ограничен 1200 px. Новые строки — в `en.ts` и
> `ru.ts`. После — `npm run typecheck` и `npm test`.

**Шаг 4, перегруз:**

> Прочитай `docs/ui/artboards/AddLot.dc.html` — там готовая логика проверки
> вместимости в `renderVals()`. Переделай `src/components/AddLotForm.tsx` в
> диалог по этому макету: панель живого расчёта справа, `window.confirm`
> заменить inline-панелью перегруза с цифрами capacity / проекции /
> перегруза, кнопка отправки активна только после чекбокса подтверждения.
> Парсинг `OVERLOAD:<json>` оставь как есть — меняется только подача.
> Проверь, что тест AT-05 в `src/services/__tests__/cargo-lot.test.ts` цел.

**Шаг 6, новый экран:**

> Прочитай `docs/ui/artboards/CargoLayers.dc.html` и `docs/ui/README.md`.
> Сделай `src/pages/CargoLayersPage.tsx` по макету. Данные: слои —
> `listHoldLots`, остатки по судам — `OgvService.availableBySource`, история
> списания — `discharge_allocations` JOIN `operations`. Высота блока слоя
> пропорциональна погруженным тоннам, списанная часть — штриховкой,
> закрытый слой — без заливки. Добавь пункт в рельс и ключи в `en.ts`/`ru.ts`.

Полезно добавлять в конец промпта: «покажи план перед тем, как править файлы»
— на шагах 5–7 это экономит переделки.
