# UI-макеты VesselAssistant

Дизайн десктопного интерфейса: 10 экранов, дизайн-система, состояния.
Живой канвас — в Claude (artifact «VesselAssistant — десктоп-интерфейс»),
здесь лежит его выгрузка, пригодная для чтения Claude Code.

## Что в папке

```
docs/ui/
├── README.md                 # этот файл — порядок внедрения и промпты
├── excel-reference.md        # разбор исходного Excel: что шире, чем в коде
├── tokens.css                # дизайн-токены, первый файл к переносу в src/styles/
├── png/                      # скриншоты артбордов (выгрузить вручную, см. ниже)
└── artboards/                # исходники макетов — точные значения px и hex
    ├── canvas.json              # раскладка канваса, размеры кадров
    ├── Main.dc.html             # 1 · Load / Stowage Plan + профиль судна
    ├── CargoLayers.dc.html      # 2 · Слои груза (LIFO)
    ├── Sof.dc.html              # 3 · Statement of Facts / Time Sheet
    ├── CraneCorrection.dc.html  # 4 · Крановая поправка
    ├── Ogv.dc.html              # 5 · OGV — загрузка AAI PRELUDE
    ├── Discharge.dc.html        # 6 · Выгрузка: превью LIFO + кран
    ├── AddLot.dc.html           # 7 · Добавление партии + AT-05
    ├── Documents.dc.html        # 8 · Документы и ревизии
    ├── Reference.dc.html        # 9 · Справочники
    └── DesignSystem.dc.html     # 10 · Дизайн-система
```

**Начинать с [`excel-reference.md`](./excel-reference.md).** Там разобрано,
чем реальная работа операторов отличается от текущей модели данных:
четыре режима крановых операций вместо `loading/discharging/shifting`,
OGV как океанское судно с семью трюмами, шапка Standard Time Sheet,
свободный объём и процент заполнения по каждому трюму. Макеты нарисованы
уже по этой логике, и часть экранов без доработки сервисов не реализуется.

## Как читать артборды

Это HTML: каждый экран — один самодостаточный файл с инлайновыми стилями.
Оттуда берутся **точные** значения: hex, размеры шрифта, отступы, высоты
контролов, ширины колонок. `grep` по ним работает:

```bash
grep -n "0B6E7F" docs/ui/artboards/*.dc.html   # где используется акцент
grep -n "font-size: 13px" docs/ui/artboards/Main.dc.html
```

Две оговорки:

- Файлы **не открываются в браузере напрямую** — они написаны в формате
  редактора Claude Design и ссылаются на `./support.js`, которого здесь нет.
  Для визуальной сверки используйте PNG (ниже) или сам канвас.
- Данные в макетах — не выдумка. Тоннажи, SF, вместимости и итоги взяты из
  `src/fixtures/kavkaz-iv.ts`, состав партий и крановые замеры — из
  исходного `Kavkaz IV_ Load St Plan+SOF.xlsx`. Все суммы сверены скриптом:
  on board `23 683.955`, Total Empty 98 % `15 881.924`, перегруз по AT-05
  `130.460` т, крановая поправка за смену `−429.029` т, cargo plan OGV
  `69 000.000` мт. Макет можно использовать как дополнительный контрольный
  пример.

### Скриншоты

Claude Code видит картинки, и для общей композиции они удобнее исходников.
В канвасе: **Share → Export → PNG**, выгрузить все артборды и положить в
`docs/ui/png/` под именами `Main.png`, `CraneCorrection.png` и т.д.
Дальше в Claude Code достаточно `@docs/ui/png/Main.png`.

## Порядок внедрения

Снизу вверх: сначала то, что ничего не ломает, потом то, что трогает
сервисы и схему БД.

1. **Токены.** Перенести `docs/ui/tokens.css` в `src/styles/tokens.css`,
   импортировать в `main.tsx` перед `App.css`, подключить IBM Plex
   Sans/Mono. Затем переписать `App.css` на токены. Поведение не меняется.
2. **Оболочка.** `App.tsx`: вместо трёх вкладок — навигационный рельс на
   разделы ТЗ §10 и шапка рейса. Контент перестаёт быть `max-width: 1200px`
   по центру.
3. **`HoldTable` + профиль судна.** Полная ширина, моноширинные числа с
   группировкой разрядов, шкала заполнения к 98 %. Над таблицей — полоса
   профиля: трюмы 5→1, два крана, `V = %` заполнения и свободный объём м³
   (обе величины выводятся из уже имеющихся данных, см. `excel-reference.md` §3).
4. **`AddLotForm`.** Диалог вместо `form-row`, живой расчёт вместимости,
   `window.confirm` → inline-панель перегруза с чекбоксом подтверждения.
5. **`DischargeForm`.** Превью LIFO до подтверждения + выбор крана и режима.
   Для превью звать `dischargeFromHold` на `structuredClone(layers)` —
   функция мутирует вход, сам `calc/discharge.ts` менять не нужно.
   В остатки списывается **вес по весам**, не скорректированный.
6. **`CargoLayersPage`.** Стек слоёв, остатки по судам-источникам,
   история списания с краном и коэффициентом.
7. **`CraneCorrectionPage`.** Требует правок модели: четыре режима вместо
   трёх типов операций и история замеров с исключением выбросов.
   Миграция + решение по открытым вопросам 1–3 из `excel-reference.md`.
8. **`SofPage`.** Шапка Time Sheet (18 полей, десять выводятся из журнала),
   суточные колонки `Disch 24hrs` / `Total disch`, таймлайн, подсветка
   пересечений.
9. **`OgvPage`.** Самый крупный кусок: сущность принимающего судна с
   трюмами, cargo plan, sequence plan и поступлениями из барж.
10. **`DocumentsPage`.** История ревизий экспорта.

Шаги 1–3 можно делать одним заходом, 4–6 — по одному в ветку. Шаги 7 и 9
начинать только после ответов заказчика на открытые вопросы.

## Чего в макете нет и что придётся решить

- **Экран ревизий предполагает, что экспорты сохраняются.** Сейчас
  `DocumentEngine` отдаёт файл и забывает о нём. Нужна таблица
  `document_revisions` (миграция + регистрация в `lib.rs` и в
  `__tests__/helpers.ts`) либо перечитывание папки рейса с диска.
- **Сводка сталии в SOF** (рабочее время, простой по погоде) — расчёта нет.
  Это чистая функция над интервалами, место ей в `src/calc/time.ts`.
- **Роли** (оператор / супервайзер / только просмотр) в макете не показаны,
  хотя ТЗ §7 их требует. Отдельная задача.
- **i18n.** Каждая новая строка — сразу в `src/i18n/en.ts` и `ru.ts`,
  иначе `npm run typecheck` не пройдёт.

## Промпты для Claude Code

Скилл `.claude/skills/ui-kit/` подхватывается автоматически. Он обновлён
вместе с макетами — свежая версия лежит в `docs/ui/ui-kit.SKILL.md`:

```bash
cp docs/ui/ui-kit.SKILL.md .claude/skills/ui-kit/SKILL.md && rm docs/ui/ui-kit.SKILL.md
```

**Шаг 3, профиль судна:**

> Прочитай `docs/ui/excel-reference.md` §3 и
> `docs/ui/artboards/Main.dc.html`. Добавь над таблицей трюмов полосу
> профиля судна по макету: трюмы 5→1, два крана с рабочим коэффициентом и
> последней операцией, под каждым трюмом процент заполнения по объёму и
> свободный объём в м³. Обе величины выводятся из `volume_m3`, `sf` и
> `remain_tons` — новых полей в БД не нужно, но в `CalculationService`
> стоит добавить `filled_volume_percent` и `free_volume_m3` рядом с
> существующим `empty_volume_percent`. Покрой их тестом: для трюма №5
> свободный объём 5 959.105 м³, заполнение 44.7 %.

**Шаг 7, краны (сначала план):**

> Прочитай `docs/ui/excel-reference.md` §2 и

> из журнала событий, плюс колонки `Disch 24hrs` и `Total disch` в таблице.
> Суточный итог считать чистой функцией в `src/calc/time.ts` с тестом.
